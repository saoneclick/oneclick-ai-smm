# AI-SMM: как устроен сценарий

## 1. Точки входа

| Событие | Кто обрабатывает |
|---|---|
| `/menu` → «🧠 AI-Маркетолог» | n8n отправляет callback в `ai_smm` |
| текст/фото/скрин в активной сессии | `ai_smm` |
| `/smm` | `ai_smm` (быстрый старт) |
| `/test_smm` | `ai_smm` (тихий тест) |
| обычные сообщения без сессии | старый n8n-сценарий |

n8n вызывает `POST http://smm:8000/event` для каждого Telegram update. Сервис
отвечает `{"handled": true|false}`:

- `true` — событие относится к AI-SMM, n8n останавливается;
- `false` — обычный сценарий продолжается.

Ответ всегда быстрый: интервью, AI и рендер выполняются в фоновой задаче, чтобы
n8n не ждал 2–3 минуты.

## 2. Состояния

```
goal → audience → topic → proof → format → cta → visual → summary
```

- `goal` — заявки / охват / доверие / запуск / партнёры.
- `audience` — владельцы / продажи / маркетинг / IT / своя.
- `topic` — повод и главная мысль.
- `proof` — реальные цифры; можно «Нет цифр».
- `format` — авто / кейс / разбор / чек-лист / история / провокация.
- `cta` — личка / заявка / ссылка / подписка / без CTA.
- `visual` — до 10 фото/скринов/URL или авто-арт; свободный текст сохраняется как
  ограничение.
- `summary` — проверка брифа, каналы, «Собрать», «Изменить», «Отмена».

Состояние хранится в `smm_sessions`:

```sql
CREATE TABLE smm_sessions (
  id bigserial PRIMARY KEY,
  chat_id bigint NOT NULL,
  status text NOT NULL DEFAULT 'active',
  step text NOT NULL DEFAULT 'goal',
  data jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX smm_sessions_one_active
  ON smm_sessions (chat_id)
  WHERE status IN ('active', 'generating', 'preview');
```

`data` содержит ответы, ассеты, каналы, `draft_id`, стратегию. На каждое действие
пишется `feedback` (approve / schedule / reject / generated).

## 3. Генерация

1. **Strategist** — угол, инсайт, 3 хука, структура, доказательства, возражения,
   визуальное направление.
2. **Copywriter** — тексты TG/VK/MAX, заголовок для карточки, подзаголовок,
   буллеты, CTA, Дзен-статья, хештеги, alt-текст, self-scores.
3. **Валидация** — длины, пустые поля, отсутствие выдуманных метрик.
4. **Cardrender** — обложка 1080×1080 с учётом темы/арта и первой картинки.
5. **Draft** — запись в `content_drafts` (`source='smm'`, `brief`, `strategy`,
   `images`, `quality_score`).
6. **Preview** — обложка/галерея + полный текст + кнопки.

Если DeepSeek вернул невалидный JSON, делается повторный запрос. Если не удалось
собрать — сессия возвращается в `summary`, пользователь видит ошибку и может
повторить.

## 4. Картинки

- Telegram `photo` — берётся самый большой размер.
- `document` с `image/*` — сохраняется как скриншот (PNG).
- URL — скачивается с проверкой content-type и лимитом размера.
- Pillow: EXIF-поворот, RGB, максимум 1800 px, JPEG/PNG, удаление метаданных.
- Файлы: `uploads/<chat_id>/<session_id>/<uuid>.jpg`.
- Media endpoint: `GET /media/<chat_id>/<session_id>/<file>`.
- Cardrender получает внутренний URL `http://smm:8000/media/...`.
- Первый файл → обложка; остальные → галерея (до 10).
- Скриншоты и портретные фото → раскладка `split`, пейзажи → `stage`.
- После публикации/отмены файлы удаляются.

## 5. Публикация

| Канал | Что отправляется |
|---|---|
| Telegram | обложка + галерея (`sendMediaGroup`), caption = TG-текст |
| MAX | загрузка каждого фото → `attachments` |
| VK | текст (фото VK пока ограничены платформой) |
| Дзен | обложка в `cards/`, статья в `articles/`, запись в `feed.xml` и `index.html` |

Статусы: `draft` → `published` / `smm_scheduled` / `rejected` / `test`.
Планировщик `ai_smm` раз в минуту публикует `smm_scheduled` и уведомляет админа.

## 6. Тихий тест

`POST /test` (или `/test_smm`):

- 3 синтетических изображения;
- реальный DeepSeek;
- реальный cardrender;
- превью в Telegram с пометкой **ТЕСТ**;
- Дзен в `tempfile`-каталоге;
- проверка конфигов MAX/VK;
- **ни одной публикации** в каналы.

Ответ — JSON с `checks`, `draft_id`, `quality_score`, `cover`, `images`.

## 7. Ошибки и деградация

- Cardrender недоступен → карточка не создаётся, но текст сохраняется.
- URL картинки не загрузился → cardrender откатывается на процедурный арт.
- MAX/VK недоступны → публикация в остальные каналы продолжается, ошибка
  показывается админу.
- Dzen-каталог недоступен → ошибка в отчёте, пост не помечается опубликованным
  только из-за Dzen.
- n8n не может достучаться до `smm` → `onError` пропускает событие в старый
  сценарий, бот не падает.

## 8. Ограничения и следующий шаг

- Старый быстрый сценарий (`➕ Новый пост`) пока не публикует в Дзен — это
  отдельная интеграция с n8n-планировщиком.
- VK-фото требуют Standalone-приложения или внешнего сервиса.
- Метрики каналов и обучение на них — следующий слой.
