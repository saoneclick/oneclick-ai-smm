# Концепция: AI-маркетолог / SMM для «One click»

Живой документ. Пополняется идеями и правилами по мере развития.

## Видение

Полноценный **AI-маркетолог/SMM-специалист**, который:
- сам готовит посты и присылает их на согласование Ивану;
- запускает публикацию **после каждого IT-свершения** (кейс, релиз, внедрение);
- учится на обратной связи (правки, отмены) и на метриках каналов;
- пишет «голосом» Ивана, а не шаблонным ИИ-языком.

## Поток «свершение → пост»

1. Иван фиксирует свершение: сообщением боту (`/done <что сделал>`), позже — автоматически из Битрикс24 (закрытая задача/проект, новый кейс).
2. Система генерирует пост-кейс (проблема → решение → результат/цифры → выгода для клиента).
3. Пост уходит Ивану на согласование с кнопками.
4. После одобрения — публикация по каналу-плейлисту (сразу или по расписанию).

## Согласование (Human-in-the-Loop)

Каждый пост приходит карточкой с кнопками:
`✅ Опубликовать · ⏰ По расписанию · ✏️ Переделать · ❌ Отмена`

«Переделать» → выбор причины (не по теме / слишком официально / длинно / нет цифр / не наш тон / плохой зачин / своя причина текстом).

## Обучение (4 слоя)

1. **Правила стиля** — из замечаний AI-«редактор» формулирует устойчивые правила, они подставляются в каждый промпт.
2. **Банк примеров** — одобренные посты как эталон, переделанные/отменённые + причина как антипример (few-shot).
3. **Метрики** — охваты/реакции/комментарии из каналов + заявки из Битрикс24 → веса форматов и тем (multi-armed bandit).
4. **Семантическая память** — pgvector, поиск примеров по смыслу; позже дообучение на парах (переделанный → одобренный).

## «Как живой человек»

- Голос Ивана: его реальные посты из `@oneclickaistudio` как эталон стиля.
- Разнообразие: 10+ форматов подачи, разная длина/зачин/призыв.
- Ритм: время постов со сдвигом, чередование рубрик (кейсы / личное / польза / события).
- Анти-ИИ-маркеры: запрет штампов, живой синтаксис, вопросы к аудитории.
- Память тем: не повторять одну тему чаще раза в 2–3 недели.

## Передача информации между проектами и сессиями

Проблема: у нас несколько агентов/проектов (разработка, поддержка, маркетинг) и разные сессии. Решения:

- **Единый источник правды — PostgreSQL.** Все компоненты читают/пишут в одну БД (черновики, отзывы, правила, примеры, метрики). Это «память» системы.
- **Событийная шина.** Внешние проекты шлют события в n8n через webhook (`/webhook/achievement`): `{source, type, title, details, link, metrics}`. Маркетинг-агент превращает событие в пост.
- **Очередь задач (Redis).** Для асинхронных заданий между агентами (генерация, модерация, публикация, сбор метрик).
- **Общий API-контракт.** Каждый агент умеет: `emit(event)`, `read_knowledge()`, `write_knowledge()`. Документируем в `docs/IDEAS.md`.
- **Правило именования сессий.** Каждая сессия агента оставляет запись в таблице `agent_journal` (кто, что сделал, что дальше) — чтобы контекст не терялся между сессиями.

## Архитектура (текущая)

`VPS (firstvds) → Docker: n8n + PostgreSQL + Redis + Caddy (HTTPS)`
- **Netlify-релей** — обход блокировки Telegram API из РФ (исходящие).
- **Long polling** Telegram через релей (входящие из Telegram в РФ блокируются).
- Каналы: Telegram, VK (текст), MAX. В планах: Дзен, TenChat, LinkedIn, e-mail (Битрикс24).

## Технические правила

- Секреты — только в `infra/*.local.env` (gitignore), в git не попадают.
- Секреты в репозиторий не коммитим.
- Согласовываем с Иваном: структуру постов, расписание, новые каналы.
- Любая новая идея/правило — дописывается в `docs/IDEAS.md`.
