# cardrender — карточки для постов

Сервис превращает заголовок поста в готовую картинку: HTML + CSS + SVG рендерятся
в PNG через Playwright. Работает без внешних картинок и без интернета — вся графика
процедурная.

## Что изменилось

Раньше все карточки были одинаковыми: градиент + заголовок. Теперь каждая карточка
собирается из трёх независимых слоёв:

| Слой | Варианты | Как выбирается |
|---|---|---|
| **Арт** | `orbit`, `grid`, `terminal`, `network`, `chart`, `guard`, `photo` | по ключевым словам заголовка, иначе детерминированно |
| **Тема** | `cyan`, `violet`, `emerald`, `amber` | детерминированно по заголовку |
| **Раскладка** | `poster`, `split`, `stage`, `stack`, `metrics` | по контенту и детерминированно |

Один и тот же пост всегда рендерится одинаково, а разные посты выглядят по-разному.
Ключевые слова влияют на арт: «бот/Telegram/n8n» → терминал, «CRM/Битрикс24/AI» →
схема интеграций, «рост/кейс/%» → график, «внедрение/запуск» → стеклянные панели,
«PHP/уязвимость/взлом/фишинг» → щит и радар.

Дополнительно:

- крупный заголовок автоматически подгоняется по ширине и высоте (без обрезки);
- цифры, проценты и ключевые слова подсвечиваются акцентным цветом;
- поддерживаются подзаголовок, 3 буллета и метрики — карточка становится информативнее;
- можно передать готовую фотографию/иллюстрацию через `image_url`;
- вертикальные сторис 1080×1920 используют те же арты и темы.

## API

`POST /card` — квадратная карточка 1080×1080

```json
{
  "headline": "Заявки из Telegram, VK и MAX — сразу в Битрикс24",
  "tag": "ИНТЕГРАЦИЯ",
  "kicker": "Кейс",
  "subtitle": "Один поток вместо трёх чатов и ручного переноса.",
  "bullets": ["Подключили каналы", "Настроили сценарии", "Вывели отчёт"],
  "metrics": [
    {"value": "3", "label": "канала в одной системе"},
    {"value": "−4 ч", "label": "рутины в день"}
  ],
  "footer_left": "Битрикс24 · AI-автоматизация",
  "footer_right": "saoneclick.ru"
}
```

Все поля, кроме `headline`, необязательны.

`POST /story_card` — сторис 1080×1920. Те же поля + `cta` (текст кнопки).

`POST /max_photo` — рендер карточки и загрузка в MAX. Дополнительно нужен `max_token`.

`GET /variants` — список доступных артов, тем и раскладок.

`GET /health` — проверка сервиса.

### Явный выбор варианта

Если нужно зафиксировать дизайн, передайте `art`, `theme` и/или `layout`:

```json
{
  "headline": "Бот, который продаёт",
  "art": "terminal",
  "theme": "amber",
  "layout": "split"
}
```

Если `art` не передан — он выбирается автоматически.

### Своя картинка

`image_url` принимает `http(s)://` или `data:image/...`. Картинка растягивается на
всю область арта и закрывается затемняющим градиентом, чтобы текст оставался
читаемым. Это точка подключения AI-иллюстраций (DALL·E, Flux, Midjourney и т.п.):
n8n генерирует картинку, кладёт её на доступный URL и передаёт в `image_url`.

```json
{
  "headline": "Автоматизация, которая освобождает время",
  "tag": "КЕЙС",
  "image_url": "https://cdn.example.com/generated/case-42.jpg"
}
```

## Как это использует бот

В Telegram достаточно отправить тему поста и ссылку на картинку **в конце сообщения**:

```
Как бот принимает картинку https://example.com/photo.jpg
```

Бот вырезает ссылку из темы, сохраняет её в `content_drafts.image_url` и передаёт
в `cardrender` при создании черновика, публикации, планировщике, MAX и сторис.
Если ссылка недоступна, сервис сам откатывается на процедурный арт.

## Запуск

В составе общего compose:

```bash
docker compose -f infra/docker-compose.yml up -d --build cardrender
```

Локально:

```bash
pip install fastapi uvicorn playwright
playwright install chromium
uvicorn app:app --host 0.0.0.0 --port 8000
```

## Шрифты

`fonts/` содержит woff2-сабсеты Inter и Unbounded (кириллица + латиница). Они
вшиваются в HTML как data URI, поэтому рендер не зависит от сети и системных
шрифтов. Лицензии — SIL Open Font License 1.1, тексты рядом с файлами.
